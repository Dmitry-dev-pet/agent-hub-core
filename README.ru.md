# Truthrail Core

[English](README.md) | **Русский**

**Один источник истины. Любой ИИ.**

Truthrail позволяет оставить ChatGPT обычным интерфейсом, а устойчивое состояние
работы хранить вне чата.

Чат может закончиться. Новый чат может продолжить работу.

Чтобы попробовать Truthrail, **не нужно** устанавливать его локально, держать Mac/PC
постоянно включённым или сразу давать ИИ право записи во весь GitHub.

## Начните с минимального доступа

Onboarding строится как лестница доверия.

### 1. Explore — только чтение

Сначала можно вообще не давать write-доступ.

Можно:

- просто дать ссылку на публичный репозиторий; или
- если подключение GitHub позволяет выбирать репозитории/read-only доступ, открыть
  только те репозитории, которые вы готовы показать Truthrail.

Напишите:

```text
Посмотри эти GitHub-репозитории через Truthrail.
Только чтение. Ничего не создавай, не изменяй и не удаляй.
Покажи, какие проекты и связи ты видишь, а всё сомнительное явно отметь.
```

На этом этапе Truthrail только читает и показывает, что понял.

### 2. Connect — один приватный репозиторий Truthrail

Если результат устраивает, Truthrail нужен один приватный репозиторий для устойчивого
контекста и маршрутизации.

Предпочтительный least-privilege вариант — создать свой приватный `truthrail`
из небольшого шаблона Truthrail Starter, когда эта кнопка доступна. Если создание из
шаблона недоступно, создайте пустой приватный репозиторий вручную. Затем разрешите AI
запись **только в него**.

Fork публичного `truthrail-core` нужен для разработки самого ядра, а не для хранения
вашего приватного instance. Проектные репозитории могут оставаться read-only.

Напишите:

```text
Создай или обнови мой приватный Truthrail instance по тем репозиториям, доступ к которым я уже разрешил.
Не запрашивай write-доступ к моим проектным репозиториям.
Не копируй значения секретов.
Проверь, что полностью новый чат может восстановить то же состояние Truthrail.
```

### 3. Познакомьтесь со своим ассистентом

Truthrail — это устойчивое состояние и протокол. Ассистент — имя и образ, с которым вы
общаетесь в чате.

Имя можно выбрать любое. `Альфред` — только имя нашего reference instance. Ваш
ассистент может быть `Nova`, `Friday`, `Ada` или называться совсем иначе.

Напишите:

```text
Моего ассистента зовут Nova.
Используй мой приватный репозиторий Truthrail как устойчивое состояние.
Проектные репозитории оставляй read-only, пока я явно не разрешу конкретную write-capability.
Запиши профиль ассистента и проверь, что новый чат восстанавливает и Truthrail, и имя ассистента.
```

Имя не является границей полномочий. Переименование ассистента не добавляет и не убирает
capabilities.

Новый ассистент получает и переносимый базовый набор навыков:

- восстановить контекст и продолжить работу;
- собрать свежую активность;
- выбрать самый узкий безопасный capability-route;
- выполнить разрешённое действие и отдельно проверить результат.

Onboarding и активация новых capabilities остаются отдельными setup/optional навыками.
См. [пример профиля ассистента](examples/assistant-profile.yaml) и
[навыки именованного ассистента](docs/assistant-skills-v0.2.md).

### 4. Operate — потом и только при необходимости

Write-capabilities подключаются отдельно, когда вы действительно хотите, чтобы
ваш ассистент/Truthrail что-то делал.

Например:

- разрешить issues/PR только в одном проекте;
- подключить конкретный deployment control plane;
- подключить machine-bound executor для Blender/GPU.

**Полный write-доступ ко всему GitHub для Truthrail не требуется.**

> Точные варианты выбора репозиториев и permissions зависят от GitHub-подключения и
> AI-клиента. Если fine-grained выбор недоступен, начать всё равно можно с публичных
> репозиториев, не подключая приватные.

## Два сценария onboarding

### В GitHub уже есть репозитории

После Explore Truthrail работает только с тем scope, который пользователь разрешил.
Он не должен утверждать, что видит репозитории вне этого scope.

Дальше он:

1. читает достаточно live evidence, чтобы понять проекты и очевидные связи;
2. не угадывает сомнительные связи, а отмечает их;
3. создаёт или обновляет один приватный Truthrail instance;
4. записывает routing, durable context, capabilities и metadata credentials без
   значений секретов;
5. проверяет результат;
6. проверяет восстановление из полностью новой сессии.

### GitHub новый и пустой

Проектов для чтения ещё нет. После разрешения создать один приватный репозиторий
Truthrail достаточно сказать:

```text
Мой GitHub-аккаунт новый, проектных репозиториев пока нет.
Настрой greenfield Truthrail.
Не придумывай проекты.
Создай один приватный репозиторий Truthrail с пустым списком проектов, базовыми GitHub capabilities и без значений секретов.
Проверь из полностью новой сессии, что пустое состояние Truthrail восстанавливается.
```

Ноль проектов — нормальное валидное состояние.

Когда позже появится первый настоящий репозиторий:

```text
Обнови Truthrail и подключи всё новое в том GitHub scope, доступ к которому я разрешил.
```

Существующий Truthrail instance обновляется, второй создавать не нужно.

## Что дальше

Работа продолжается в обычном чате.

Например:

```text
Nova, продолжай.
```

Новая сессия находит текущий durable run, перечитывает live state GitHub/control
planes, продолжает работу, проверяет результат и только после verification закрывает run.

Truthrail намеренно разделяет выполнение и проверку:

```text
executing -> executed -> verifying -> verified
```

`executed` означает, что исполнитель закончил операцию. Само по себе это ещё не успех.
`verified` — конечное состояние run, в которое он переходит только после проверки
авторитетных evidence. Для продолжения из новой сессии durable run может хранить короткий
checkpoint, а опциональный Truthrail Watch может заметить устаревший lifecycle status, но
не меняет его автоматически.

## Что хранит Truthrail

Truthrail может хранить:

- routing проектов и aliases;
- устойчивые цели, решения и ограничения;
- metadata capabilities;
- имена/scopes/routes credentials, но не значения секретов;
- durable work/run state;
- ссылки на авторитетные live systems.

Актуальные ветки, PR, Actions, deployments и runtime status перечитываются из живой
системы.

## Чем Truthrail не является

Truthrail — это не:

- отдельное приложение для чата;
- постоянно работающий центральный agent daemon;
- secret manager;
- универсальный remote shell;
- требование держать компьютер включённым;
- требование дать write-доступ ко всему GitHub-аккаунту.
